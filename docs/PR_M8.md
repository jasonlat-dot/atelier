# M8 套餐、订单与订阅

用户可以在现有「积分与订阅」工作台选购套餐、创建订单、查看付款状态和取消待付款订单。管理员从「套餐与订单」管理商品、确认线下到账、核对未消费部分的退款金额，并登记已经完成的线下退款。当前为人工收付款，不接在线网关，不会自动扣款或续费。

## 使用

1. 重启根目录 `npm run dev`，启动时自动应用 M8 两个新增迁移，不需要新密钥。
2. 管理员进入 `/admin/plans`，创建并上架积分包或订阅套餐。价格单位为分；订阅另设周期、结转、并发、分辨率和新素材保留时间。默认没有示例商品。
3. 用户进入 `/wallet` →「套餐与订阅」，核对套餐并创建订单；随后查看「我的订单」，联系管理员核对收款方式并线下付款。创建订单不会扣款。
4. 管理员在「订单管理」核对原订单金额、币种和真实收款凭证号，再确认到账。有效 MFA、Origin、CSRF、管理员权限均由后端检查。
5. 退款前在订单中重新核对可退金额。完成线下退款后，再勾选确认并登记；此按钮不会自动转账。有任务预占时先等任务结束或取消，再重新核对。
6. 兑换码在「积分账本」使用；管理员从侧栏「积分管理」进行人工调整，或进入「兑换码管理」生成、查询和复制兑换码。套餐与订单仅管理套餐、订单、到账和退款。2026-10-24 修订后，新码使用现有 MASTER_KEY 派生的独立密钥加密保存，可在列表中按需复制；列表本身仍只返回元数据。旧版仅存哈希的码无法恢复完整内容，其兑换能力保持原样；重启后端应用 `202610241200_redeem_code_recovery.sql` 后新生成的码才支持恢复。

## 事务与权益

- 下单冻结完整套餐快照；后续改价、下架不修改历史订单。订单快照、收款凭证与终态受数据库保护，不能回退重发。
- 订单创建、收款和退款使用 UUID 幂等键；付款金额/币种必须匹配原快照，收款凭证全局唯一。并发重试只产生一次 PURCHASE；付款、钱包、订阅、审计同事务。
- 每笔 MONTHLY 订单购买一个已付款周期。再次购买顺延到已有周期后，周期开始时最多发放一次积分。每日后台维护与相关请求同步推进，权益按数据库时间即时生效或到期降级；完全错过的周期中，不结转的过期积分不补发，可结转的已付款积分补发一次。
- 生成 limits、quote 和 create 使用当前套餐的分辨率与并发限制。新上传或生成的素材使用当前保留期，历史素材到期时间不追溯改写。
- 钱包继续是单一余额。FIFO 入账份额跟踪每笔订单未消费积分，旧余额迁移为开账份额；消费、退款和到期回收仍只通过 wallet 模块及不可修改账本。
- 退款按未消费份额比例计算，金额向下取整到分；排期尚未开始的周期可全额退。任务有预占时阻止退款，防止破坏进行中任务；退款登记同时回收未用积分并结束对应订单的周期权益。
- 不结转的周期积分到期回收，可结转的积分保留。预占部分延后回收，释放后的下一次相关请求或每日维护继续处理，账户权益仍按时到期。
- 套餐下架是 active=false；用户只能取消本人的 PENDING。订单按创建时间与 ID 稳定分页，跨用户详情/游标不会泄露订单。

- `services/api/crates/app/src/billing_http.rs`、`routes.rs`、`main.rs`：权限接口与后台维护；生成/素材模块读取实时权益。
- `apps/web/src/features/billing`、`features/wallet/WalletPage.tsx`：套餐、权益、订单和管理员表单，沿用工作台及自定义可访问弹窗。

## 边界与停止点

在线支付、验签 webhook 和自动扣款不在本轮；ManualProvider 没有匿名回调入口。每日维护不是支付网关，只处理已经付费的周期。商用套餐价格、实际收款渠道、真实退款到账及供应商效果由部署者核对。S3 与视频尾帧协议扩展继续待定。

本轮完成 M8 后停止，不自动进入 M9。下次从管理后台里程碑继续，先读 PROGRESS、DECISIONS 和负责人最新授权。
